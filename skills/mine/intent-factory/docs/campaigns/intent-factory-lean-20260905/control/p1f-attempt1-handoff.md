## Root causes found and fixed (done)

1. **Notification popups**: `test/helpers.mjs` now defaults `INTENT_FACTORY_NOTIFY_BIN` to a generated no-op script at import time when unset, so no test spawns real `osascript`. Tests needing a specific/absent transport still set/restore it themselves (existing pattern kept).

2. **`orphan()` test helper didn't match the worktree era**: after a full completion, a node's `worktree.status` is `"removed"`. Tests that call `orphan()` to simulate a crash need a *real* worktree back (adoption/resume calls `settleDone` which needs `attemptWorkspace(state)`). Added `ensureAttemptWorktree(runDir, state)` to `test/helpers.mjs` (uses `createAttemptWorktree` from `scripts/worktree.mjs` to recreate the worktree from the still-existing git branch when `status === "removed"`), and `orphan()` now calls it automatically. Exported and imported in `runner.test.mjs`; used explicitly (with `state.worktree = ensureAttemptWorktree(runDir, state)`) in several hand-rolled fixtures that mutate node.json directly without calling `orphan()`.

3. **`recoverIntegrationTransactions`' `onAccepted` in `runner.mjs` (~line 2001) unconditionally forced node status to `"done"`** whenever `state.status !== "done"`, even when the transaction had already been fully applied earlier and something else (test, or a distinct legitimate recovery concern) later reset the node. Fixed by adding a `hasDoneEvent(runDir, nodeId, attempt)` helper (extracted from `ensureTerminalEvent`, checks `events.jsonl` for an already-recorded `to === "done"` transition for that node+attempt) and skipping the whole block when `hasDoneEvent(...)` is true. This was the single biggest root cause — it was silently intercepting resume for ~15+ tests before they ever reached `recoverOrphan`, producing `result: null` (`Cannot read properties of null (reading 'summary')`) or empty results.

4. **`backoff.mjs` `planRoute`**: the `provider_failover_cycle` detection was unreachable because `nextSynthesizedRuntime`'s own attempted-filter already excluded the cycling candidate before the `attempted.has(fallback)` check ran. Fixed by resolving the raw declared candidate via `synthesizedChain(...)` separately (imported it) and checking `attempted.has(declaredCandidate)` explicitly to decide between `provider_failover_cycle` and the original error code.

5. **Contract fixtures using `exec-jsonl`/`replay` drivers without an explicit `vendor`** now fail `validateContract` (`resolveVendor` returns null for these two drivers — this is intentional design, see `drivers/index.mjs` `DEFAULT_DRIVER_VENDORS` comment). Added `vendor: "..."` to every such runtime declaration across `runner.test.mjs` (search for `"exec-jsonl"` in that file — all should now have `vendor:` fields).

6. **`doctor`**: two fixtures created a git repo with no commit; per this node's decision, `doctor` must report an unborn repo as a failing `git` check (this was *already* implemented via `environmentPreflight`'s `checkGit` — no runner.mjs change needed). Fixed the two doctor tests in `runner.test.mjs` by giving their fixture repos one commit (`-c commit.gpgSign=false`), and added a new test `"doctor reports an unborn repository as a failing git check"` right after the first doctor test.

7. **Cross-vendor gate test**: `"a judge that lost its socket takes the network backoff..."` used the same runtime id for worker and judge — now correctly rejected by the (pre-existing) worker/judge-share-vendor validation. Split into two runtimes (`primary-worker`, `primary`) with distinct vendors, same executable.

8. **`failoverEdges`/`nextSynthesizedRuntime` role param**: `"failoverEdges lists one declared edge per runtime..."` test asserted judge failover was worker-only; that's now explicitly false by design (judge fallback admissibility is vendor-checked at routing time in `runner.mjs`, not at this layer). Updated the assertion with a comment explaining the removed behavior (carve-out case, named).
